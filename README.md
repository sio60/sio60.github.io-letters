# 편지

하루에 한 장씩 자동으로 열리는 편지 앱. **Android에 설치해서 사용하거나, 웹 주소로 열 수 있습니다.** QR에는 설치 파일 다운로드 주소 또는 웹 주소를 넣어 전달합니다.

## Android에 설치해서 전달하기

무늬 없는 흰 편지지와 단정한 글자로 구성한 Android 앱입니다. 글꼴과 편지는 앱에 포함되어 있어 설치 후 인터넷 없이 읽을 수 있습니다.

```bash
flutter pub get
flutter test
flutter build apk --release
```

빌드한 파일은 `build/app/outputs/flutter-apk/app-release.apk`입니다. `letter-clean-preview.apk`는 이전 디자인 확인용 파일이므로 현재 배포본이 아닙니다. 현재 설정은 `unlockAllForPreview = false`이며 2026년 10월 10일부터 하루 한 장씩 열립니다. APK를 별도로 전달하려면 최신 소스로 다시 빌드하고, 계속 보관할 배포 서명을 설정하세요.

QR 전달 순서: APK를 내려받을 수 있는 주소 준비 → 휴대폰에서 다운로드·설치 확인 → 그 주소를 QR 코드로 인쇄. 직접 설치 시 다운로드한 브라우저의 ‘이 출처의 앱 설치 허용’이 필요할 수 있습니다. QR은 설치 파일 자체가 아니라 다운로드 주소를 담습니다. 설치 후 편지 내용을 바꾸려면 같은 서명으로 새 버전을 빌드해 업데이트해야 합니다.

Windows에서 한글 폴더 경로로 Flutter/Gradle 오류가 나면 영문 경로의 임시 폴더에 소스를 복사해 빌드하세요.

## 1. 편지 쓰기

[`letters/letters.txt`](letters/letters.txt) 하나만 고치면 됩니다.

```
== 1 ==
첫 번째 편지

여기부터 본문. 줄바꿈도 빈 줄도 그대로 나옵니다.

== 2 ==
두 번째 편지의 제목

본문...
```

- `== 숫자 ==` 다음부터 다음 구분선 전까지가 **편지 본문**입니다. 별도 제목은 자동으로 분리하지 않습니다.
- 파일 맨 위 첫 구분선 앞의 내용은 전부 무시되니 메모해도 됩니다.
- 총 66장 중 아직 쓰지 않은 날에는 **글감**이 남아 있습니다. 공개일 전에 해당 내용을 편지로 바꿔주세요.

다 쓰면 반영:

```bash
dart run tool/build_letters.dart
```

## 2. 설정하기

[`lib/config.dart`](lib/config.dart) 에서:

| 항목 | 설명 |
|---|---|
| `startDate` | **1일차가 열리는 날짜.** 이 날부터 하루에 한 장씩 해금됩니다 |
| `recipientName` | 받는 사람 (화면 상단, 편지 첫머리에 표시) |
| `senderName` | 보내는 사람 (편지 끝에 표시) |
| `totalDays` | 총 편지 수. 원고 개수와 맞춰주세요 |
| `entryStartDate` | 본문 아래에 표시할 첫 편지의 날짜. 공개일과 별개입니다 |
| `unlockAllForPreview` | 날짜 잠금을 해제하는 미리보기 설정. 배포 시 `false` |
| `finaleMessage` | 66일을 다 읽은 뒤 나오는 한 줄 |

첫 화면은 날짜별 편지 목록입니다. 오른쪽 위에는 오데, 열린 날짜 칸에는 치이카와·하치와레·우사기·오데·고블린이 순서대로 표시됩니다. 편지 본문은 그림 없는 흰 편지지이며, 앱 아이콘은 단순한 봉투 모양입니다. 캐릭터 원본 출처는 `assets/chiikawa-artwork-source.txt`에 기록했습니다.

## 4. 배포하기

`main` 브랜치에 푸시하면 GitHub Actions가 자동으로 빌드해서 GitHub Pages에 올립니다.

**최초 1회 설정:** 레포 Settings → Pages → Source를 **GitHub Actions**로 변경.

주소는 https://sio60.github.io/sio60.github.io-letters/ 입니다. 이 주소를 QR 코드로 만들어 전달할 수 있습니다.

> 레포 이름을 바꾸면 [`deploy.yml`](.github/workflows/deploy.yml)의 `--base-href /sio60.github.io-letters/`도 같이 바꿔야 합니다.

이후 `letters/letters.txt`를 수정해 `main`에 올리면 같은 주소로 자동 업데이트됩니다. 웹을 다시 열거나 새로고침하면 최신 편지가 로드되므로 QR 코드를 다시 만들 필요가 없습니다. 이미 읽은 표시는 같은 브라우저에 유지됩니다.

## 5. 상대 폰에 "앱처럼" 넣기

스토어 설치는 없습니다. 대신 PWA로 설정해뒀기 때문에 홈 화면에 아이콘을 만들 수 있습니다.
아이콘은 봉투 모양([`web/icons/`](web/icons))이고, 설치한 아이콘으로 열면 독립된 앱 창으로 표시됩니다.

- **아이폰 (Safari)** — 링크 열기 → 하단 공유 버튼 → `홈 화면에 추가`
- **안드로이드 (Chrome)** — 링크 열기 → 우상단 ⋮ → `홈 화면에 추가` (또는 자동으로 뜨는 설치 배너)

> 아이폰은 반드시 **Safari**로 열어야 합니다. 카카오톡 인앱 브라우저에서는 "홈 화면에 추가"가 없으니,
> 링크를 보낼 때 "사파리로 열어서 홈 화면에 추가해줘"라고 한마디 덧붙이면 됩니다.

진짜 네이티브 앱(스토어 설치)이 필요하면 안드로이드는 APK 직배포가 가능하지만, 아이폰은 TestFlight나
앱스토어 심사를 거쳐야 해서 편지 하나 보자고 하기엔 과합니다.

## 동작 방식

- **해금** — `startDate + (N-1)일`이 지나면 N일차가 열립니다. 날짜 기준이라 상대가 기기나 브라우저를 바꿔도 동일하게 동작합니다.
- **읽음 표시** — 브라우저 `localStorage`에 저장됩니다. 편지를 어디까지 읽었는지는 기기별로 기억되고, 지워져도 편지가 잠기지는 않습니다.
- **서버 없음** — 편지는 앱 번들에 내장됩니다. 서버 비용도, 계정도 없습니다.

## 알아두실 점

편지 내용은 [`lib/data/codec.dart`](lib/data/codec.dart)의 XOR + Base64로 난독화되어 번들에 들어갑니다. **암호화가 아닙니다.** 이 저장소와 웹사이트는 공개되며, 저장소의 편지 원문 또는 배포 파일에서 잠긴 날짜를 포함한 66일치 데이터를 확인할 수 있습니다. 날짜 잠금은 화면 표시 기능이며 접근 제한이 아닙니다.

이걸 완전히 막으려면 편지를 서버에 두고 날짜가 됐을 때만 내려주는 구조(Firebase 등)가 필요합니다.
